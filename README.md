# 战舰世界自动战斗控制台

> 在 Windows 本地运行的《战舰世界》自动战斗控制台：在网页中选择舰船、战斗模式和停止条件后，程序自动完成启动游戏、港口检查、选择舰船、加入战斗、闭环驾驶、战斗控制、结算收益和下一局。

- 仓库：<https://github.com/chongfenglaosiji/wowws-bot>
- 版本：见 [`VERSION`](VERSION)
- 平台：Windows 10 / 11（64 位） · Python 3.11（64 位）

> **免责声明**：本项目仅用于本地研究与受监督测试。游戏自动化可能违反游戏服务条款并带来账号风险；程序不规避反作弊，也不会在画面、输入或状态无法确认时盲目继续操作。请自行承担使用风险。

## 功能特性

- **一键启动**：双击 `start_project.bat` 自动完成解释器检测、虚拟环境创建、基础依赖与 CUDA 组件安装、控制台启动和浏览器打开，无需手敲 Python 命令。
- **两种客户端**：Steam 版与 WG Game Center 版（直接启动游戏本体），按区服版本自动选择可执行文件。
- **两种模式**：联合作战、非对称作战。
- **舰船支持**：波美拉尼亚、那不勒斯，以及按港口名称填写的自定义舰船。
- **视觉闭环**：截图识别 → 决策 → 输入派发 → 小地图位移/画面反馈验证；证据不足时等待而不是盲操作。
- **NVIDIA OCR 自动部署**：检测到 NVIDIA 显卡时自动安装 CUDA/cuDNN OCR 组件并做实机推理验证；无显卡或安装失败时自动回退 CPU。
- **自动航行**：开局用 M 地图多帧投票锁定山体与占领点，之后由小地图持续更新自身位置、航向、敌舰与岛屿，自动选择航向、绕岛与进点。
- **战斗控制**：主炮/副炮射击、R 损管、T/U/Y 消耗品、那不勒斯烟雾、近距离鱼雷自动瞄准与发射。
- **结算与续局**：通过标题与资源列识别胜负和收益；能直接“继续战斗”时续局，不行则回港兜底。
- **安全暂停**：切屏或键盘介入时冻结自动输入；暂停期间不抢焦点，恢复前重新识别当前画面。
- **控制台**：八套主题、实时状态、本组累计、任务历史、实时日志、截图统计与清理、版本更新检查、中断任务接续。
- **启动服务质量**：依赖检查缓存、CUDA 安装结果缓存、控制台单实例、快速就绪探测、可调启动超时、日志自动滚动。

## 环境要求

必需：

- Windows 10 或 Windows 11（64 位）；
- 64 位 Python 3.11（脚本只接受 3.11 / 64 位，不会用其他版本代替）；
- Steam 版或 WG Game Center 版《战舰世界》；
- 首次安装依赖时能够联网。

建议：

- 解压到普通磁盘目录（例如 `E:\wowws_bot\`），不要直接在压缩包内运行；
- 避免桌面、OneDrive 同步目录或包含特殊符号的深层目录；
- 显卡 OCR 为可选项（NVIDIA CUDA）：检测到 NVIDIA 显卡时首次启动会自动安装 CUDA/cuDNN 组件，缺失或安装失败时自动回退 CPU，不影响基本运行。

## 快速开始

### 方式一：下载 ZIP

1. 在仓库页面点击 **Code → Download ZIP**；
2. 完整解压到新文件夹；
3. 双击根目录的 `start_project.bat`。

### 方式二：Git 克隆

```powershell
git clone https://github.com/chongfenglaosiji/wowws-bot.git
cd wowws-bot
.\start_project.bat
```

以后更新：

```powershell
git pull --ff-only
.\start_project.bat
```

### 启动脚本做了什么

第一次运行会依次：

1. 查找可用的 64 位 Python 3.11（`py`、PATH、注册表、常见安装目录）；
2. 在项目内创建 `.venv` 并安装 `requirements.txt`；
3. 检查依赖能否真实导入（失败会修复）；
4. 检测 NVIDIA 显卡：自动安装 CUDA/cuDNN OCR 组件并验证，无显卡或失败时回退 CPU；
5. 启动本地控制台并等待接口就绪；
6. 打开 <http://127.0.0.1:8899/>。

检测到 NVIDIA 显卡时，首次启动还需要下载 CUDA/cuDNN 组件，可能多花几分钟。详细的 pip 与 CUDA 安装过程写入 `data/install.log`；CUDA 安装失败不会阻塞启动，OCR 会自动使用 CPU。

以后启动会复用 `.venv`、基础依赖检查缓存和 CUDA 安装结果，通常几秒内完成；如果控制台已经在运行，脚本只打开网页，不会重复启动服务。

失败时窗口会保留原因，详细日志在：

```text
data/startup.log                 启动脚本日志（超过 1 MB 自动滚动为 .1）
data/control_server.stderr.log   控制台进程错误
```

只做 Python 检测、不创建环境：

```powershell
.\start_project.bat -CheckPythonOnly
```

使用自定义位置的 Python：

```powershell
$env:WOWS_PYTHON = 'D:\Python311\python.exe'
.\start_project.bat
```

## 使用流程

1. **选择游戏客户端**：Steam 或 WG 版。按钮下方会显示检测到的路径；当前选择未找到时，实时日志会给出原因。WG 模式不会自动回退到 Steam，避免启动错误账号或区服。
2. **选择战斗模式**：联合作战或非对称作战。
3. **选择舰船**：
   - 预设舰船：波美拉尼亚、那不勒斯；
   - 自定义舰船：名称必须与港口显示完全一致，并填写副炮射程（1.0–30.0 km），可保存为预设复用。
4. **设置停止条件**：完整局数（1–100）、运行时长（1–1440 分钟）或不限。
5. **按需勾选**：快速战斗、完成后关闭游戏、运行完关机。
6. **点击“开始自动战斗”**。

运行中主按钮会变为“暂停 / 继续”，右侧“终止任务”会结束本次计划。手动终止的任务不会作为续接候选；运行进程异常退出且计划未完成时，面板会提示“继续”，并保留已完成局数与用时。

## 运行逻辑

### 场景识别与入局锁

程序把当前画面归类为港口、加载/匹配、战斗、结算、未知遮挡等状态，并为每个状态选择安全的下一步。点击“加入战斗”后，本局会被锁定到连续确认结算页为止；期间即使某帧画面短暂误判为港口，也不会回到选船流程，只有连续确认结算才计入一局。

未知页面只有在顶部角落确认 `Esc ×`、`Esc 关闭` 或 `Esc 返回` 等关闭提示后，才可能累计最多三次 Esc；每次按键前重新截图复核，提示消失即停止。存在比赛计时、血量等实时战斗证据时只观察不点击。沉没后的观战画面仍属于战斗，底部“Esc 离开战斗”不会被当作关闭遮挡的依据。

### 自动航行

- 开局打开 M 地图，多帧投票锁定本局山体与占领点；自身位置、航向和敌舰由右下角小地图持续更新。
- 黄色射程圈仅作辅助；没有黄色圈时，唯一且形状明确的白色箭头仍可用于定位。
- 航向走廊只检查舰艏前方，左右各投射一条候选通道，优先选择净空更大的一侧；连续两帧确认地形后才触发转舵。
- 岛屿紧急避让 > 鱼雷规避 > 常规绕岛 > 进点推进；点外全速，接近点位后减速留守。
- 航点点击后等待绿色“自动驾驶”文字，同时用实际位移和航速验证；控制台显示实际下发的 Q/E 或“原生自动舵”。

### 战斗控制

- 主炮与副炮按识别到的 HUD 状态开火；未实现的副炮锁定不再发送定时 X 按键。
- **R 损管**：确认着火/进水时尝试 R；8 秒内掉最大血量 8% 且下一次新鲜血量读数复核仍处于低血量时，或 8 秒内至少两次独立下降、累计掉最大血量 0.3%（跨度≥2 秒）时也会尝试。按键间隔默认 3 秒（仅表示尝试间隔，实际冷却由游戏判定）；输入失败会保留受损证据稍后重试。阈值可在 `config/ship.yaml` 调整。
- **其他消耗品**：血量 ≤ 80% 时每 30 秒尝试 T/U/Y；那不勒斯血量 < 50% 时使用烟雾。
- **近距离鱼雷**：先用两次新截图确认“3 号键位 + 鱼雷图标”，在 0.25–6 km（含边界，已知舰船还受射程限制）内识别装填、发射方向与白色提前量扇区，连续两帧对齐后才点击一次左键。装填中、目标丢失、暂停、沉没、菜单或分辨率变化都会取消本次发射；单次瞄准总限时默认 30 秒，每次输入要求截图不超过 4 秒。
- **鱼雷目标搜索**：主视野没有敌舰时，小地图连续三帧确认 6 km 内的同一敌舰，可在验证存活、自身箭头、红色目标和 3 号武器后有限移动镜头；每局有步数与冷却预算，搜索不改变自动航线。

### 结算与收益

- 完整结算页的胜负通过“胜利/失败”标题文字识别，并经至少两次读数确认；无法确认时保留为未知，不猜测败局。
- 收益每次重新采集当前画面，不复用战斗阶段缓存；资源数值需要多帧共识，最多重试三组、每组六帧。
- 若仍未识别但结算页已确认，会保存诊断截图、将收益记为“未识别”并继续计划，不累计不可靠数字。
- 优先点击“继续战斗”；不可用时自动回港，再从港口常规入口开始下一局。

### 快速战斗

勾选后，单局达到 5 分钟、确认沉没或离开战斗 HUD 时会退出本局并继续下一局。快速战斗计入计划局数，但不统计收益和胜负。

### 完成后动作

“完成后关闭游戏”和“运行完关机”只会在整组计划正常完成时生效；暂停、手动终止或异常结束都不会触发。

## 暂停与人工介入

- 单纯移动或点击鼠标不会触发自动暂停。
- 按键盘或切换到其他窗口会暂停新的自动操作。
- 用户仍在持续操作时，程序不会强行切回游戏。
- 停止操作并连续静默 5 秒后，程序才会尝试返回游戏，并从当前画面重新识别流程。
- 持续操作达到 20 秒后会锁定暂停；此时需要回到网页点击“继续”，或回到游戏窗口并静默后自动解除切屏暂停。
- 在网页主动点击“暂停”后，必须点击“继续”才会恢复。
- 暂停期间暂时找不到游戏窗口也不会终止任务；继续后会等待窗口重新出现，再从当前阶段接续。
- 暂停、切屏、自动恢复和手动继续都会写入实时日志。恢复时不会沿用暂停前的旧按钮或旧页面。

## 控制台说明

- **主题切换**：右上角可在「黑金 / 浅金 / 中灰 / 灰白 / 深蓝 / 暖褐 / 青灰 / 紫灰」八套配色间切换，选择保存在浏览器本地；也可用 `?theme=classic|light-gold|mid-grey|mono|navy|amber|teal|violet` 指定。
- **当前状态**：任务阶段、计划进度、运行时间、航线阶段与进度、距点位、目标距离、舰船/模式、视觉与位移反馈、自动航行与舵位、小地图态势、舰体状态、航速、消耗品状态。
- **本组累计**：完整战斗的银币、舰船经验、全局经验、局数和累计用时；下方有任务历史记录。
- **实时日志**：显示任务阶段、识别结果、输入派发与恢复过程；建议排查问题时先看最后几行。
- **截图**：显示生成截图的占用情况，任务停止后可一键清理。
- **版本更新**：控制台启动后会在后台检查仓库最新版本，发现新版本时“更新”按钮显示红点；点开可查看当前版本、最新版本、最近提交和活跃用户统计。检查结果缓存 6 小时，失败后 15 分钟再试。
- **任务接续**：运行进程异常退出后，若原计划尚未完成，面板会显示“继续”，点击后从原进度接续；手动终止的任务不会被接续。

## 启动脚本与本地服务

启动链：`start_project.bat` → `tools/start_project.ps1` → `control_server.py` → 浏览器。

- **依赖检查缓存**：首次验证通过后写入 `data/.deps-ok.json`。只有解释器、`requirements.txt` 或已安装包发生变化时才重新执行耗时导入检查，重复启动通常只需几十毫秒。怀疑依赖损坏时可强制重查：

  ```powershell
  $env:WOWS_FORCE_DEP_CHECK = '1'
  .\start_project.bat
  ```

- **就绪等待**：默认最多等待 45 秒，先密后疏探测接口；慢磁盘可放宽：

  ```powershell
  $env:WOWS_STARTUP_TIMEOUT = '90'
  .\start_project.bat
  ```

  成功启动时会输出“总耗时 N 秒”，等待期间每 5 秒提示一次进度。

- **单实例与端口**：默认独占监听 `127.0.0.1:8899`（可用 `WOWS_PANEL_PORT` 修改）。重复双击只会打开已运行的网页；真正被其他程序占用时，进程会在几秒内以退出码 2 结束并给出中文原因。运行中的控制台会在 `data/control_server.json` 记录端口与版本，便于启动脚本跨端口复用。

- **权限**：控制台默认以普通权限运行。只有检测到游戏确实以管理员权限运行、普通输入会被 Windows 拦截时，点击“开始自动战斗”才会弹出一次 UAC 确认并自动续接。

- **CUDA 自动安装**：检测到 NVIDIA 显卡时，按 `requirements-gpu.txt` 自动安装 CUDA/cuDNN OCR 组件，并用真实推理验证；结果写入 `data/.gpu-deps.json` 缓存，失败约 6 小时后重试并回退 CPU。跳过或强制重装：

  ```powershell
  $env:WOWS_SKIP_GPU_INSTALL = '1'    # 跳过 CUDA 安装
  $env:WOWS_FORCE_GPU_INSTALL = '1'   # 忽略缓存立即重装
  ```

- **日志**：
  - `data/startup.log`：启动脚本日志，超过 1 MB 滚动为 `startup.log.1`；
  - `data/install.log`：pip 与 CUDA 组件安装明细，超过 2 MB 滚动为 `install.log.1`；
  - `data/control_server.stdout.log` / `data/control_server.stderr.log`：控制台进程输出（每次启动覆盖）；
  - `data/runtime.log`：当前任务的运行日志；
  - `wowws_bot.log`：运行器日志，5 MB × 3 自动滚动。

- **失败退出码**：启动脚本成功返回 `0`，失败返回 `1`；直接运行 `control_server.py` 时，端口冲突或参数非法返回 `2`。

## 配置与环境变量

舰船与策略参数集中在 [`config/ship.yaml`](config/ship.yaml)，包括副炮射程、鱼雷距离、损管阈值、消耗品阈值、航行参数等；网页“自定义舰船”只填写名称与副炮射程，其余使用保守的通用策略。

以下环境变量按需使用，未列出的 `WOWS_*` 由控制台在启动任务时自动传给运行进程。

### 启动与控制台

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `WOWS_PYTHON` | 自动检测 | 指定 64 位 Python 3.11 的 `python.exe` |
| `WOWS_PANEL_PORT` | `8899` | 控制台端口（1–65535） |
| `WOWS_PANEL_HOST` | `127.0.0.1` | 监听地址，默认只允许本机访问 |
| `WOWS_PANEL_NO_BROWSER` | 空 | 设为 `1` 时不自动打开浏览器 |
| `WOWS_STARTUP_TIMEOUT` | `45` | 等待控制台就绪的秒数（最小 5） |
| `WOWS_FORCE_DEP_CHECK` | 空 | 设为 `1` 时忽略依赖检查缓存 |
| `WOWS_SKIP_GPU_INSTALL` | 空 | 设为 `1` 时跳过 CUDA/cuDNN 组件安装 |
| `WOWS_FORCE_GPU_INSTALL` | 空 | 设为 `1` 时忽略 CUDA 安装缓存，立即重新安装 |

### 任务参数（网页会自动设置）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `WOWS_SHIP` | `pommern` | 舰船键名：`pommern` / `napoli` / `custom` |
| `WOWS_MODE` | `asymmetric` | `cooperative` 或 `asymmetric` |
| `WOWS_OCR_DEVICE` | `nvidia` | OCR 设备：`nvidia` 或 `cpu` |
| `WOWS_INPUT_BACKEND` | `windows_native_keyboard` | 输入后端，可选 `vgamepad_xbox360`（需已安装 ViGEm 驱动） |
| `WOWS_DEBUG_KEEP_RUNS` | `200` | 本局诊断目录保留数量；磁盘不足时自动跳过并记录 |

### 游戏定位与启动

| 变量 | 默认 | 说明 |
| --- | --- | --- |

- 每局确认完成后会封存该局证据并删除更早的局，只保留最近完整一局；进行中的局不会中途清理。需要释放空间时，可在任务停止后使用控制台的“清理截图”。

## 常见问题

### 双击后没有打开网页

先等待首次依赖安装完成，也可以手动打开 <http://127.0.0.1:8899/>。启动脚本会检查 `py`、PATH 中的 `python`、Python 安装注册表及常见目录，并显示实际选中的解释器。失败详情见 `data/startup.log`，控制台进程错误见 `data/control_server.stderr.log`。

可以先运行只读诊断：

```powershell
.\start_project.bat -CheckPythonOnly
```

### 提示找不到可用的 Python

本项目要求 64 位 Python 3.11：

- 32 位、3.10、3.12 及以上版本不会被接受；
- Microsoft Store 的未安装占位别名会被跳过；
- 已安装但未加入 PATH 的常规安装可以通过注册表识别；
- 也可以用 `WOWS_PYTHON` 指定完整路径。

### 安装依赖失败

检查网络后再次双击即可，已安装成功的内容会复用。NVIDIA OCR 组件安装或验证失败时会自动回退 CPU，不影响基本运行。详细安装过程见 `data/install.log`。

### CUDA 组件安装失败或很慢

首次启动检测到 NVIDIA 显卡时，会下载并安装 CUDA/cuDNN 组件，可能耗时数分钟，日志写入 `data/install.log`。

- 安装失败不会阻塞启动，OCR 自动回退 CPU；
- 约 6 小时后再次启动会自动重试；
- 想立即重试：`$env:WOWS_FORCE_GPU_INSTALL = '1'`；
- 只想用 CPU：`$env:WOWS_SKIP_GPU_INSTALL = '1'`；
- 安装完成后可用 `tools/check_ocr_acceleration.py` 查看实际推理设备。

### 启动很慢或依赖检查反复进行

第二次及以后启动会复用依赖检查缓存；只有解释器、`requirements.txt` 或已安装包变化时才重新验证。CUDA 组件安装成功后也会走缓存，不再重复下载。需要强制重查时设置 `WOWS_FORCE_DEP_CHECK=1`。首次解压、杀毒软件扫描或首次安装 CUDA 期间可适当调大 `WOWS_STARTUP_TIMEOUT`。

### 端口被占用

默认端口 `8899` 被其他程序占用时，控制台会在几秒内报错并提示更换端口：

```powershell
$env:WOWS_PANEL_PORT = '9001'
.\start_project.bat
```

如果已有控制台在运行，重复双击只会打开它的网页，不会启动第二个服务。

### 显示“游戏画面不可用”

确认游戏没有最小化，并等待日志重新绑定游戏窗口。一般无需管理员权限；仅当游戏自身以管理员权限运行时，“开始自动战斗”会提示一次 UAC。拒绝 UAC 时任务不会启动，也不会发送无效指令。

### 想更新程序

先看控制台右上角“更新”：红点表示仓库已有新版本。使用 Git 的用户执行 `git pull --ff-only`；下载 ZIP 的用户重新下载并解压到新文件夹。个人运行数据在 `data/` 和 `runtime/`，更新不会覆盖这些目录。

## 已知限制

- 仅支持 Windows；仅支持 64 位 Python 3.11。
- 视觉识别存在不确定性：画面、输入或状态无法确认时，程序会选择等待、重新识别或停止，而不是猜测执行。
- 部分诊断截图目录硬编码在 `E:/aimemo/docs/screenshots/`；无该磁盘或目录不可写时只跳过诊断写入。
- GPU OCR 需要 NVIDIA 驱动与 CUDA 运行组件；不可用时回退 CPU，识别速度会下降。
- 不规避反作弊，不保证账号安全，也不提供任何形式的可用性承诺。
